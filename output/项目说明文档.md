## 1. 项目概述

### 1.1 项目简介

听书知识库是一个基于 **RAG（检索增强生成）** 技术构建的智能听书问答与推荐系统。系统面向听书平台场景，支持有声书信息、书籍简介、作者介绍、听书笔记、推荐运营资料、用户评论摘要和常见问答等内容的高效管理。

### 1.2 核心能力

- **智能文档导入**: 支持 PDF/Markdown 格式听书资料导入，自动提取元数据
- **混合向量检索**: 采用 Dense + Sparse 双路向量检索 + RRF 融合排序
- **意图识别路由**: 自动识别用户问题类型（推荐/详情/笔记/问答）
- **多场景问答**: 支持书籍推荐、详情查询、笔记检索、知识问答四种场景
- **流式输出**: 支持 Server-Sent Events 实时流式回答
- **可视化控制面板**: 提供 Web 管理界面进行服务控制和对话

### 1.3 技术栈

| 层级 | 技术选型 | 用途说明 |
|------|----------|----------|
| **后端框架** | FastAPI 0.135+ | 高性能异步 HTTP 服务 |
| **工作流编排** | LangGraph 1.1+ | 状态机驱动的业务流程 |
| **LLM 框架** | LangChain 1.2+ | 大模型调用与链式组合 |
| **向量数据库** | Milvus 2.6+ | 存储 BGE-M3 的 dense+sparse 向量 |
| **对象存储** | MinIO | 文档原始文件存储 |
| **文档数据库** | MongoDB 4.16+ | 对话历史持久化 |
| **嵌入模型** | BGE-M3 (FlagEmbedding) | 1024维 dense + sparse 向量 |
| **重排序** | BGE-Reranker-v2 | 多路召回结果精排 |
| **LLM 提供商** | 阿里 DashScope (qwen-flash) | 文本生成与理解 |
| **文档解析** | MinerU SDK / magic-pdf | PDF 转 Markdown |
| **前端** | 原生 HTML/CSS/JS | 暖色调武侠风 UI |

## 2. 业务背景与需求

### 2.1 项目背景

面向听书平台场景，系统需要接入多种类型的听书相关内容，并提供智能化的问答与推荐能力，解决以下痛点：

- 听书资料分散，缺乏统一知识库
- 用户难以快速找到感兴趣的书籍
- 书籍详情信息不结构化，查询效率低
- 听书笔记和评论散落各处，无法有效检索

### 2.2 功能范围

#### 内容导入
- 支持 PDF/Markdown 格式听书资料导入
- 自动任务状态追踪与元数据管理
- 支持手动补充书籍元数据（书名、作者、类别、时长等）

#### 书籍推荐
- 按书名、作者、类别、场景标签等条件查找
- 返回书籍列表、书籍特色、适合人群和推荐理由

#### 书籍详情
- 查询书籍简介、作者介绍、有声书时长、演播信息
- 返回内容标签、听书亮点和常见问题

#### 内容检索
- 定位书籍资料与听书笔记
- 返回书名、作者名、内容类型、文件名等来源信息

#### 知识问答
- 基于知识库内容生成答案
- 返回必要的引用信息

### 2.3 内容类型定义

知识库中每条内容属于以下类型之一：

| 内容类型 | 说明 | 示例 |
|----------|------|------|
| 有声书信息 | 演播、时长、出品方等 | "演播：某主播，时长：12小时" |
| 书籍简介 | 内容概要、故事梗概 | "《三体》讲述了..." |
| 作者介绍 | 作者生平、创作风格 | "刘慈欣，中国科幻作家..." |
| 听书笔记 | 精选笔记、心得体会 | "本书精彩之处在于..." |
| 推荐运营资料 | 官方推荐语、运营文案 | "编辑推荐：..." |
| 用户评论摘要 | 用户评价精华 | "听众@A 说：..." |
| 常见问答 | 高频问题与解答 | "Q: 这本书适合谁听？" |

## 4. 核心功能模块

### 4.1 导入流程 (Import Pipeline)

#### 流程图

```
[Upload] → [node_entry] → [PDF→MD?] → [MD处理] → [切分] → [元数据提取] → [主体识别] → [向量化] → [入库]
               ↓               ↓
            入口判断         图片处理
```

#### 节点说明

| 节点 | 功能 | 输入 | 输出 |
|------|------|------|------|
| `node_entry` | 入口路由，判断文件类型 | local_file_path | is_pdf/is_md, local_dir |
| `node_pdf_to_md` | MinerU SDK 解析 PDF | pdf_path | md_content, md_path |
| `node_md_img` | 下载 MD 内嵌图片到 MinIO | md_content, md_path | md_path, images |
| `node_document_split` | Markdown 标题语义切分 | md_path | chunks[] |
| `node_book_meta_extract` | LLM 提取听书元数据 | chunks | book_title, author, category... |
| `node_item_name_recognition` | LLM 识别主体名称 | chunks | item_name, vectors |
| `node_bge_embedding` | BGE-M3 生成向量 | chunks | dense_vector, sparse_vector |
| `node_import_milvus` | 写入 Milvus | chunks, item_name | 导入状态 |

#### 关键实现

**文档切分策略** (`split_service.py`):
- 基于 Markdown 标题正则 `^#{1,6}\s.+`
- 保留标题层级关系（`title`, `parent_title`）
- 自动处理代码块（``` 包围），避免误切
- 兜底策略：无法切分时整文档作为单一块

**主体识别** (`item_name_service.py`):
- 取前 5 个 chunk（共不超过 3000 字符）构建上下文
- 调用 LLM 识别文档主体名称（如 "HAK 180 烫金机"）
- 主体名称单独生成向量并写入独立 Milvus Collection (`tingbook_item_names`)
- 所有 chunks 关联该 `item_name`，支持后续检索时过滤

**元数据提取** (`book_meta_service.py`):
- 两步 LLM 调用：① 内容类型分类 ② 结构化元数据提取
- 提取字段：`book_title`, `author`, `category`, `duration`, `highlights`, `faq`, `narrator`
- 分类枚举：有声书信息/书籍简介/作者介绍/听书笔记/推荐运营资料/用户评论摘要/常见问答
- 类别枚举：小说/非小说/儿童/教育/历史/科幻/悬疑/言情/经管/心理/哲学/传记

```python

- `recommend`: "推荐几本科幻小说"

## 5. 数据流程详解

### 5.1 导入全流程

```
1. 用户上传文件 (POST /upload)
   ↓
2. 保存到本地 output/YYYYMMDD/{task_id}/
   ↓
3. 异步调用 LangGraph 导入流程
   ↓
4. [node_entry] 判断文件类型
   ├─ PDF → node_pdf_to_md (MinerU 解析)
   │   ↓
   │   [MD 生成] → md_path
   │
   └─ MD → 直接读取
   ↓
5. [node_md_img] 处理 Markdown 内嵌图片
   - 下载图片到 MinIO
   - 替换 MD 中图片链接为 MinIO URL
   ↓
6. [node_document_split] 切分文档
   - 基于标题切分，保留层级
   - 附加听书元数据到每个 chunk
   ↓
7. [node_book_meta_extract] 提取元数据
   - LLM 分类内容类型
   - LLM 提取结构化元数据
   - 更新 state 并回写到 chunks
   ↓
8. [node_item_name_recognition] 识别主体
   - LLM 识别 item_name
   - 生成 item_name 向量
   - 写入 tingbook_item_names Collection
   - 更新所有 chunks 的 item_name 字段
   ↓
9. [node_bge_embedding] 生成向量
   - BGE-M3 批量生成 dense + sparse 向量
   - 分批处理（每批 5 条）
   - 向量写入 chunks
   ↓
10. [node_import_milvus] 入库
    - 写入 tingbook_chunks Collection
    - 写入 tingbook_meta Collection（元数据+向量）
    - 返回导入状态
```

### 5.2 查询全流程

```
1. 用户发起查询 (POST /query)
   ↓
2. 创建 session_id，初始化 QueryGraphState
   ↓
3. [node_item_name_confirm] 提取主体名称
   - 使用 LLM 从问题中识别提到的书籍名
   - 如果无法识别且无历史答案 → 提前结束返回询问
   - 如果能识别 → 继续
   ↓
4. [node_intent_classify] 意图识别
   - LLM 判断问题类型
   ↓
5. 分支路由:
   ├─ recommend → [node_recommend]
   │   - 检索相关书籍，LLM 生成推荐理由
   │   ↓
   │   [node_answer_output]
   │
   ├─ detail → [node_book_detail]
   │   - 从 Milvus 查询书籍元数据
   │   - 聚合生成结构化详情
   │   ↓
   │   [node_answer_output]
   │
   ├─ note → [node_book_note]
   │   - 检索听书笔记和评论
   │   ↓
   │   [node_answer_output]
   │
   └─ search/qa → 并行执行:
       ├─ [node_search_embedding] (BGE-M3 向量检索)
       │   - dense_vector: COSINE 相似度
       │   - sparse_vector: IP (Inner Product)
       │
       ├─ [node_search_embedding_hyde] (HyDE)
       │   - LLM 生成假设答案
       │   - 用假设答案再检索
       │
       └─ [node_web_search_mcp] (网络搜索)
           - MCP 工具补充外部知识
       ↓
   [node_rrf] RRF 融合
   - 加权合并三路召回结果
   - 公式: score = Σ(1 / (k + rank_i))
   ↓
   [node_rerank] BGE-Reranker 精排
   - 对 Top-K 结果重排序
   - 取最终 Top-N 作为上下文
   ↓
   [node_answer_output]
   - 构建 prompt（参考内容+历史+问题）
   - LLM 生成最终答案
   - 流式/非流式输出
   - 保存对话历史到 MongoDB
```

## 6. 关键技术解读

### 6.1 RAG 检索增强生成

#### 双路向量检索 (Hybrid Search)

```python
# 创建检索请求
dense_req = AnnSearchRequest(
    data=[dense_vector],
    anns_field="dense_vector",
    param={"metric_type": "COSINE"},
    limit=limit
)
sparse_req = AnnSearchRequest(
    data=[sparse_vector],
    anns_field="sparse_vector",
    param={"metric_type": "IP"},
    limit=limit
)

# 使用 RRF 融合
from pymilvus import RRFRanker
ranker = RRFRanker(k=limit)
results = client.hybrid_search(
    collection_name=collection,
    reqs=[dense_req, sparse_req],
    ranker=ranker,
    limit=limit
)
```

**技术原理**:
- **Dense Vector**: BGE-M3 生成 1024 维语义向量，捕捉深层语义相似性
- **Sparse Vector**: BGE-M3 同时生成关键词级稀疏向量，保留精确匹配能力
- **RRF (Reciprocal Rank Fusion)**: 对两路结果的排名进行加权融合，避免单一召回策略的偏差

**为什么用 RRF 而不是加权分数**:
- 不同检索方式的分数分布不同（COSINE vs IP），直接加权不公平
- RRF 基于排名位置计算，更加鲁棒
- 公式: `RRF_Score = Σ (1 / (k + rank_i))`，k 通常取 60

#### HyDE (Hypothetical Document Embedding)

```python
# 1. 生成假设答案
hypothesis = llm.invoke("请回答：{query}")

# 2. 对假设答案编码
hyde_vector = embed(hypothesis)

# 3. 用假设答案向量检索
results = search(hyde_vector)
```

**优势**: 将 "问题 → 答案" 的语义差距缩小，提高召回准确率

#### Reranker 精排

```python
# BGE-Reranker-v2 对召回结果重排序
reranker = get_reranker_model()
pairs = [(query, doc.text) for doc in docs]
scores = reranker.compute_score(pairs)
```

**作用**: 解决召回阶段 "粗筛" 与 "精度" 的矛盾，对 Top-K 候选做精细化排序

### 6.2 LangGraph 状态机编排

#### 状态定义

```python
class ImportGraphState(TypedDict):

```

#### 条件路由

```python
def node_entry_after(state: ImportGraphState) -> str:
    if state["is_md_read_enabled"]:
        return "node_md_img"
    elif state["is_pdf_read_enabled"]:
        return "node_pdf_to_md"
    return END
```

**优势**:
- 每个节点职责单一，便于测试与维护
- 状态在节点间传递，无需全局变量
- 支持并行分支（查询时向量、HyDE、Web 搜索并行）

### 6.3 BGE-M3 Embedding 模型

BGE-M3 是 FlagEmbedding 发布的多语言 Embedding 模型，支持三种向量输出：

| 向量类型 | 维度 | 用途 | 相似度度量 |
|----------|------|------|-----------|
| Dense | 1024 | 语义相似性 | COSINE |
| Sparse | 词汇维度 | 关键词匹配 | Inner Product (IP) |
| ColBERT | 词级别向量 | 细粒度匹配 | - |

**本项目使用**: Dense + Sparse 双路

```python
# 调用方式
result = llm_provider.embed_documents(["文本1", "文本2"])
# result = {"dense": [[...], [...]], "sparse": [{...}, {...}]}
```

### 6.4 Milvus 集合设计

#### Collection 1: `tingbook_chunks` (文档块)

| 字段 | 类型 | 说明 |
|------|------|------|
| `pk` | INT64 | 主键 |
| `content` | VARCHAR | 文本内容 |
| `title` | VARCHAR | 块标题（Markdown 标题） |
| `parent_title` | VARCHAR | 父标题 |
| `file_title` | VARCHAR | 文件名 |
| `item_name` | VARCHAR | 主体名称 |
| `book_title` | VARCHAR | 书名 |
| `author` | VARCHAR | 作者 |
| `category` | VARCHAR | 类别 |
| `content_type` | VARCHAR | 内容类型 |
| `duration` | VARCHAR | 时长 |
| `highlights` | VARCHAR | 亮点 |
| `faq` | VARCHAR | 常见问题 |
| `narrator` | VARCHAR | 演播者 |
| `source_path` | VARCHAR | 来源路径 |
| `dense_vector` | FLOAT_VECTOR | 1024 维稠密向量 |
| `sparse_vector` | SPARSE_FLOAT_VECTOR | 稀疏向量 |

**索引配置**:
- Dense: HNSW, COSINE, M=64, efConstruction=100
- Sparse: SPARSE_INVERTED_INDEX, IP, DAAT_MAXSCORE

#### Collection 2: `tingbook_item_names` (主体名称)

| 字段 | 类型 | 说明 |
|------|------|------|
| `pk` | INT64 | 主键 |
| `file_title` | VARCHAR | 文件名 |
| `item_name` | VARCHAR | 主体名称 |
| `book_title` | VARCHAR | 书名 |
| `dense_vector` | FLOAT_VECTOR | 主体名称向量 |
| `sparse_vector` | SPARSE_FLOAT_VECTOR | 主体名称稀疏向量 |

**用途**: 实体消歧、主体过滤、同义词扩展

#### Collection 3: `tingbook_meta` (听书元数据)

结构与 `tingbook_chunks` 的元数据字段一致，但每个 `book_title` 只保留一条记录（去重），用于快速查询书籍详情。

## 10. 已知问题与修复

### 10.1 历史问题

| 问题 | 原因 | 修复方案 |
|------|------|----------|
| 导入服务间歇性失败 | `book_title`/`file_title` 为 `None` 导致 Milvus insert 跳过字段报错 | 添加 None 检查，使用默认值 `"未知"` |
| 日志编码失败 | Windows 后台进程默认 cp1252 编码，中文输出失败 | `logger.py` 添加 `sys.stdout.reconfigure(encoding="utf-8")` |
| 端口配置不一致 | 各服务硬编码不同端口 | 统一为 8001/8002/8080，通过 `settings_config.py` 管理 |
| pymilvus 3.0 API 不兼容 | `hybrid_search()` 使用 `ranker=` 而非 `rerank=` | 更新为 `from pymilvus import RRFRanker` + `ranker=RRFRanker(k=limit)` |
| Milvus `id` 字段类型不确定 | VARCHAR vs INT64 混用导致 `id > 0` 过滤失败 | 使用 `file_title != ""` 作为安全过滤条件 |
| 查询服务启动失败 (2026-07-24) | `_build_cmd` 错误选择 Linux venv（依赖不完整） | 优先级改为 Windows venv 优先，同步修复模型路径跨平台转换 |
